# Contribution Guidelines

Thanks for wanting to contribute to Awesome MCP!

## Adding something to the list

Open a pull request that adds a single entry per line, in this format:

```markdown
- [Name](https://link-to-project) — Short description of what it does.
```

Use an em dash (—) between the link and the description.

## Requirements for an entry

Before opening a PR, check that the project:

- Is genuinely related to the Model Context Protocol (a server, client, SDK, framework, registry, or learning resource).
- Is publicly accessible and has a working link.
- Is actively maintained — a project with no commits or releases in the last year is unlikely to be accepted.
- Has a README or documentation explaining what it does and how to run it.
- Is placed in the most appropriate existing section. If none fits, propose a new section in your PR description and explain why.

## Style

- Keep descriptions to one sentence, and describe what the project *does* — not how great it is. Avoid marketing language.
- Start descriptions with a capital letter and end with a period.
- Keep entries within a section alphabetically ordered where the existing section already follows that convention.
- Do not add your own project more than once, and disclose in the PR if you are the author.

## Removing an entry

If a listed project is abandoned, has been archived, or its link is dead, open a PR removing it and note the reason.

## Pull requests

- One logical change per PR.
- Give the PR a descriptive title, e.g. `Add Foo server to Databases`.
- If a maintainer asks for changes, push follow-up commits to the same branch.

By contributing, you agree that your contribution is released under the same CC0 license as the rest of this repository.
